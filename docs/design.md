# guitar-drill 設計

ギタリストが覚えること（指板の音名、度数の位置、コードの型、ダイアトニック、モード…）を、
初心者→中級者→上級者の順に覚えていく暗記ドリル。iPhone のホーム画面アプリ（PWA）として
GitHub Pages から配る。

旧アプリ [diatonic-drill](https://github.com/uekei0612/diatonic-drill) はこのアプリの
「ダイアトニックコード」1 分野にあたる。コードは持ち込まず、計算の考え方とテストの事例だけを参考にする
（[reference-diatonic-drill.md](reference-diatonic-drill.md)）。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 配り方 | PWA（GitHub Pages、`main` への push で公開）。`develop` は同じサイトの `/guitar-drill/dev/` に公開（記録の保存先は `guitar-drill-dev` に分け、本番の service worker は `/dev/` を受け持たない） | 主な使い方が iPhone のホーム画面。オフラインでも動かす。Pages は 1 リポジトリ 1 サイトなので、develop は下の階層に置き、どちらへの push でも両方をビルドし直す |
| 言語・ビルド | TypeScript + Vite | 分野が増えても型で守る。ビルドは GitHub Actions で行う |
| UI | Preact | 画面が多くなるので部品化したい。実行時 4KB 程度で軽い |
| テスト | Vitest（理論・出題・記録）、Playwright（画面） | 理論は DOM に触らない純粋関数にして単体テストで固める |
| PWA | vite-plugin-pwa（新しい版は自動で切り替える。ドリルの画面にいる間は待ち、出たところで再読み込み） | word-sprint で、更新の反映が遅れる問題を経験済み |
| 記録 | localStorage、版付きスキーマ＋移行関数、JSON の書き出し／読み込み | ホーム画面版は Safari と保存領域が別なので、最初から移せるようにする |
| 開発環境 | Docker の `node:22-alpine`（dev VM の Node は 16 で Vite が動かない） | dev サーバーは 8008 番（HTTP）。実機で SW を試すときは NPM で HTTPS を被せる |
| ブランチ | feature → develop → main | `main` への push がそのまま本番 |
| スケールの資料 | guitar_chart をモジュールとして取り込み、guitar_chart は廃止する | 資料（チャート）とドリルを 1 つのアプリにまとめる（下の「チャート」） |

## 構成

```
src/
  theory/        音楽理論。DOM に触らない純粋関数（音名・音程・スケール・コード・キー・指板）
  topics/        分野。1 分野 = 1 ディレクトリ（出題・参考ページ）
  drill/         出題エンジン（分野の共通インターフェース、出題順、採点）
  store/         記録（スキーマ、移行、書き出し／読み込み）
  ui/            画面と部品（指板 SVG、4択、結果）
```

### 理論（`src/theory`）

音は「音名（文字＋変化記号）」で持ち、ピッチクラス（0〜11）は計算で出す。
F♯ と G♭ を区別しないと調の綴りが壊れるため（旧アプリで実証済み）。

- `Note`：`{ letter: 0..6, acc: -2..2 }`。`pc()`、`fmt()`（♯♭表記）
- `Interval`：度数（1〜13）と質（P/M/m/A/d）。半音数と相互変換
- `spell(root, intervals)`：ルート＋音程の並び → 正しく綴った音名の並び
- `Scale`：メジャー、ナチュラル／ハーモニック／メロディックマイナー、チャーチモード、ペンタ、ブルース
- `Chord`：型（構成音程の並び）と表記。トライアド、4和音、テンション
- `Key`：調号、ダイアトニックコード（マイナーの Ⅴ・Ⅶ を借りる設定は旧アプリから引き継ぐ）
- `Fretboard`：チューニング（既定は標準）、`(弦, フレット) → 音`、`音 → 指板上の位置一覧`

### 分野（`src/topics`）

すべての分野が同じインターフェースを実装する。新しい分野を足しても出題エンジンと記録は変えない。

```ts
interface Topic {
  id: string;               // "fret-notes" など。記録のキーになるので変えない
  level: "beginner" | "intermediate" | "advanced";
  title: string;
  items(settings): ItemId[]; // 覚える単位（例：「6弦 5f」「C メジャーの Ⅴ」）
  question(item, settings, rng): Question;
  reference?: Component;     // 参考ページ（旧アプリの「覚え方」にあたる）
}

type Question = {
  prompt: Prompt;            // 文 or 指板図つき
  answer: ChoiceAnswer | FretTapAnswer; // 4択 or 指板をタップ
};
```

`rng` を渡すのは、出題をテストで再現できるようにするため。

### 出題順（`src/drill`）

覚える単位（item）ごとに、間を空けて繰り返す（簡易 SM-2）。
旧アプリはキー単位で苦手を優先していたが、指板の音名などは item が数百あるため、
「まだ出していないもの」と「忘れかけたもの（期限切れ）」から出す方式にする。

- item ごとに `{ ease, interval, due, tries, correct }`
- 正解で間隔を延ばし、誤答で短く戻す。1 セッションは 20 問程度
- 分野ごとの「習熟度」＝期限内の item の割合を一覧に出す

### 記録（`src/store`）

- localStorage のキーは 1 つ。`{ version, settings, items: { "<topicId>/<itemId>": stat } }`
- 読み込み時に版を見て移行し、値は 1 つずつ検証する（壊れた値は既定値に戻す）
- 設定画面から JSON を書き出し／読み込みできる（Safari ↔ ホーム画面版の移行用）

### チャート（旧 guitar_chart を取り込んだもの）

スケール指板の資料を作るアプリ [guitar_chart](https://github.com/uekei0612/guitar-chart) を、このアプリの
1 つのモジュール（`src/chart`）として取り込み、guitar_chart は廃止する。
**チャートで見て覚え、ドリルで覚えたか確かめる**を、1 つのアプリの中で行う。

最初は guitar_chart を別アプリのまま、定義を JSON で取り込み（`npm run sync:guitar-chart`）、
「guitar_chart で開く」リンクでつないでいた。ユーザーの判断で、2 つを保守し続けるより 1 つにまとめることにした
（2026-10-26）。

| 項目 | 決定 | 理由 |
|---|---|---|
| 置き場所 | `src/chart`（画面は `#/chart`）。理論は `src/theory` に足す | ドリルと同じ理論コアを使い、綴り（F♯ と G♭）も揃う |
| ボックスの位置 | guitar_chart の計算（`compute_box_fret_ranges`）を TypeScript に移す | サーバーを持たない。移したあと、guitar_chart の全組み合わせと一致することをテストで確かめてから JSON の取り込みをやめる |
| PDF | jsPDF でブラウザの中で作る（使うときだけ読み込む） | ユーザーの選択。印刷用ページでなく、今と同じく PDF ファイルを直接ダウンロードできるようにする |
| PDF の作り方 | ページを「図形の並び（mm 単位）」として組み立て、同じものを SVG（画面のプレビュー）と PDF の両方に描く | プレビューと PDF の見た目がずれない。レイアウトを単体テストできる |
| PDF の文字 | 英語（今の guitar_chart と同じ） | 日本語フォントを PDF に埋め込むと数 MB になる |
| 画面の言葉 | 日本語だけ | guitar_chart の英語表示は引き継がない（ユーザーの判断） |
| 公開中の guitar_chart | ここで同じことができるのを確かめてから、Cloud Run と自宅の本番・dev を止め、リポジトリをアーカイブする | ユーザーの判断（停止して誘導） |

#### 取り込む機能

- 指板：スケール（guitar_chart の 11 種）／アルペジオ（10 種）／カスタム（12 の度数から選ぶ）、キー、
  チューニング（guitar_chart の 23 種と、自分で決める 4〜8 弦）、カポ、度数／音名、♭表記、左利き
- CAGED ボックス：帯で示す・1 つだけ表示する。指板の音をタップして度数を足し引きする（カスタムになる）
- 試聴（Web Audio で上行）、画像保存（PNG）、今の状態を再現するリンク
- PDF：ボックス図（5 パターン）、度数付き全指板（ボックスの帯つき）、全 12 キー（1 ページあたりのキー数を選ぶ）

取り込まないもの：英語表示、CLI だけにあるマイナー／メジャーの組み資料（Web からは使えなかった）。

guitar_chart の挙動から 1 つだけ直す：標準チューニングで例のキーを canonical root 以外にすると、
度数付き全指板の帯が canonical root の位置のままになっていた。帯もキーに合わせて動かす。

#### 画面での指板

ドリル用の指板 SVG 部品（`src/ui/Fretboard.tsx`）を広げて使う（ボックスの帯、カポ、開放弦の音名、
置いていない位置のタップ）。スマホでは縦向き（ナットが上）、横幅の広い画面では横向きで 15 フレットまで出す。

### 画面

1. **ホーム**：一番上に「次にやること」（期限の来た問題があれば全分野まとめた「今日の復習」、無ければ続きの分野）。
   その下にレベル別の分野一覧。行には「覚えた数／全体」（時間が経っても減らない）と「復習待ち」の数を出す
2. **ドリル**：問題 → 回答 → 正誤と解説（指板図で答えの位置を示す）
3. **参考**：分野ごとの覚え方（図つき）
4. **設定**：チューニング、左利き表示、ライト／ダーク、記録の書き出し／読み込み

画面の下にタブ（ドリル／チャート／設定）を置き、ホームを経由せずに行き来できるようにする（参考はドリルのタブの中）。
ドリルを解いているあいだはタブを出さない。

指板 SVG は 1 つの部品にして、表示・出題・回答（タップ）・解説のすべてで使う。

指板の向き：

- **ドリルの図はすべて横向き（1 弦が上・6 弦が下、TAB と同じ）にそろえる**。問題や分野ごとに頭の中で
  図を回して読み直させないため（2026-10-29 に、7 フレット以上を縦向きにしていたのをやめた）
- 7 フレット以上（指板の音名の 12 フレットまで）は、縮めずに本来の大きさ（1 マス 56×48）で描き、
  図だけを横スクロールにする。画面の幅に詰めると 1 フレット約 24px に潰れて押しにくく、形も読みにくいため
  （2026-10-29 に詰める方式から変えた）。問題が変わるとナットの側に戻す
- 縦向き（ナットが上、6 弦が左）はチャートのスマホ表示だけで使う
- チャートは資料なので、スマホでは縦、横幅の広い画面では横（上の「画面での指板」）

アクセシビリティは旧アプリで整えたもの（タブのキーボード操作、`aria-live` での正誤読み上げ、
44px 以上のタップ領域）を最初から入れる。

## 分野の予定

| レベル | 分野 |
|---|---|
| 初心者 | 開放弦の音名 ／ ローコードの押さえ方 ／ 指板の音名（自然音・12 フレットまで） ／ ハイコードの押さえ方 ／ メジャー・マイナーの構成音 |
| 中級者 | スケールのボックス（チャートと連携） ／ 指板の音名（全音） ／ 度数の位置 ／ ダイアトニックコード ／ 4和音の構成音 ／ 五度圏と調号 ／ 定番の進行 |
| 上級者 | モードの特性音 ／ テンションの構成音 ／ ドミナントで使うスケール ／ セカンダリードミナントと裏コード |

スケールの分野（ペンタ、メジャー／マイナー、モード、ブルース、ハーモニックマイナー）は、
チャートと同じ度数とボックスを使い、「ボックス N の中で、この点は何度？」「ボックス N の R を全部タップ」
「このボックスで抜けている音をタップ」を出題する。

コードの押さえ方（ローコード・ハイコード）は、押さえ方を「6弦→1弦のフレット」と「指番号」で持ち、
縦向きのコードダイアグラム（ナットが上、× と白抜きの ○、バレーの帯、指番号／度数の切り替え）で見せる。
「押さえ方を作る」は鳴る位置を 1 弦 1 か所ずつタップし（鳴らす開放弦は開放の欄、鳴らさない弦は押さない）、
ハイコードはルートを示して残りを埋める。ハイコードはさらに「ルートは何フレット」「形を見て名前」
（もう一方のルート弦で読んだ名前を引っかけにする）を出す。形はレギュラーチューニングのものなので、
ほかのチューニングでは出題しない。ハイコードを指板の音名（既定は 6弦・5弦）のあとに置くのは、
ルートの位置を読めることが前提だから。

指板の型のうちボイシング（ドロップ 2 など）は、指板タップで「型を埋める」出題として
上の分野が揃ったあとで足す。
