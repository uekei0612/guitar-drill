# 旧アプリ diatonic-drill から引き継ぐもの

[diatonic-drill](https://github.com/uekei0612/diatonic-drill) はこのアプリの「ダイアトニックコード」分野の前身。
コードは持ち込まず、次の考え方と事例だけを引き継ぐ。

## 計算

- **綴り**：音名の文字は「ルートの文字＋度数−1」で決め、変化記号は半音数の差から出す
  （`theory.js` の `spell`）。これで全 24 キーがダブル♯／♭なしで綴れ、G♯m の導音は F𝄪 になる。
- **キーの集合**：五度圏の並びを正本にして、♯系→♭系の並びは調号の数から導く。F♯ と E♭m は異名同音で揃える。
- **コードの型**：スケール上で 3度ずつ積み、ルートからの半音数の組で型（M7, 7, m7, m7(♭5), dim7）を判定する。
- **マイナーの Ⅴ・Ⅶ**：ナチュラルマイナーを基本に、Ⅴ と Ⅶ だけハーモニックマイナーから借りる設定。
  ほかの 5 つとスケールの音はナチュラルのまま。dim7 の第7音は「6」ではなく「♭♭7」と書く。

## 出題

- **紛らわしい選択肢**：正解と同じルートで型違い、ルートを半音ずらした同じ型、同じキーの別のコード、
  異名同音、の順に混ぜてから 4 つに切る。重複は除く。
- テストは「全キー × 全形式 × 50 回で、選択肢が重複せず正解を含む」を回していた。新しい出題エンジンでも
  分野ごとに同じ性質テストを書く。

## 失敗から学んだこと

- **記録のキーの衝突**：メジャーとマイナーを `m:A` のように同じ ID で記録していて、A と Am の成績が混ざった。
  → item ID は分野と種別を含めて一意にし、途中で変えない。
- **設定の書き込み先の取り違え**：画面ごとの設定ボタンが別の画面の設定を書き換えていた（`settings.undefined`）。
  → 設定は型で縛り、画面ごとに持つ設定を分ける。
- **保存値の検証**：localStorage の値を検証せずに使うと、版を上げたときに壊れる。
  → 読み込み時に版を見て移行し、値を 1 つずつ検証する。
- **狭い画面**：360px 幅＋ダークモードでタブが折り返した。→ 画面は 360px 幅で確認する。

## 画面

- 「全一覧（めくって覚える）」と「覚え方（図つきのカンニングペーパー）」は好評だった。
  新アプリでは各分野の「参考」ページとして持つ。
- アクセシビリティ：WAI-ARIA のタブ（矢印キー・Home/End）、`aria-live` での正誤の読み上げ、
  ボタン群の `role=group` とラベル付け。
